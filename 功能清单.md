# Visual AI Coding 功能清单

可视化管理 Claude Code 与 Codex 的配置、插件与工具。技术栈：Electron + React + TypeScript + Tailwind CSS + Ant Design。

## 统一配置

| 功能名           | 一句话用途                                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------------- |
| 统一 MCP 编辑    | 用中立 JSON 只写一次 MCP server（名称/命令/参数/环境变量），存放于 ~/.visualAiCoding/unified/mcp.json       |
| MCP 双端同步     | 一键把统一 MCP 块替换写入 Claude 的 ~/.claude.json 与 Codex 的 config.toml，带托管标记不覆盖用户手动 server |
| 统一 Skills 软链 | 把 ~/.visualAiCoding/unified/skills 下技能软链到两端 skills 目录，改一处两端生效，遇同名真实目录跳过并警告  |
| 同步结果反馈     | 逐项展示各能力写入的目标路径、条目数与非致命警告                                                            |

## 性能与体验基础层

| 功能名               | 一句话用途                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| 主进程异步化         | 启动时 SSH_AUTH_SOCK 和登录 shell PATH 均改为 async 预热，不再冻结主进程事件循环                |
| IPC Handler 全量异步 | listDir、listClaudeOutputStyles、listSkills 等扫描函数改用 fs.promises 并发读取，解除主进程阻塞 |
| SkillsPage 并发防护  | loadSkills 引入序号机制，快速重刷时旧请求结果被丢弃，不覆盖最新状态                             |
| 技能分类、筛选与分页 | 默认展示 Codex，可按工具和动态来源筛选 Skill，并按窗口高度自动调整 Ant Design 表格分页条数      |
| 标准状态色           | 成功、警告与危险提示使用清晰的通过绿、提醒黄和错误红，提升状态辨识度                            |

| 功能名           | 一句话用途                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| 工具安装探测     | 探测本机 Claude Code / Codex CLI 是否安装、版本与可执行路径                                                |
| 重新探测         | 手动刷新工具安装状态                                                                                       |
| CLI 最新版更新   | 查询 npm 最新版本时同步刷新本地探测，并按 Volta 或 npm 安装来源更新 Claude Code / Codex CLI 后校验真实版本 |
| CLI 更新内容入口 | 查询最新版本后可从工具卡片打开官方 changelog 或 releases 页面查看更新内容                                  |
| 配置目录入口     | 展示 ~~/.claude、~~/.codex 目录路径，一键 Finder / VSCode 打开                                             |
| 快速跳转         | 从工具卡片直接进入对应配置管理页                                                                           |

## Claude Code 配置页

| 功能名             | 一句话用途                                                                            |
| ------------------ | ------------------------------------------------------------------------------------- |
| settings.json 编辑 | 可视化查看并编辑 Claude 核心设置（环境变量、模型、权限、hooks）                       |
| 字段 key 展示      | 每个可视化配置项展示对应真实英文字段路径，便于对照官方文档和原始配置                  |
| 字段状态标识       | 已设置字段显示绿色状态胶囊和圆点，未设置字段保持中性，快速区分配置覆盖情况            |
| 字段默认值展示     | 有官方文档明确默认值的字段展示"默认值：xxx"，帮助判断未设置字段的实际生效行为         |
| 输出风格校验与创建 | 检查 outputStyle 是否对应内置或自定义风格，并可创建缺失的 output-styles Markdown 文件 |
| 高级字段保留       | 可视化保存时保留 schema 未覆盖字段，并在高级字段区域查看实际内容                      |
| 统一保存 loading   | 配置加载、整体保存与字段级保存展示一致的等待图标和禁用态                              |
| CLAUDE.md 编辑     | 编辑全局指令文件                                                                      |
| 插件清单查看       | 只读展示 installed_plugins.json                                                       |
| 市场清单查看       | 只读展示 known_marketplaces.json                                                      |

## Codex 配置页

| 功能名            | 一句话用途                                                                 |
| ----------------- | -------------------------------------------------------------------------- |
| config.toml 编辑  | 可视化编辑 Codex 核心设置（模型、provider、沙箱、审批策略）                |

## 插件管理页

| 功能名                   | 一句话用途                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Claude 插件更新状态      | 展示 Claude 插件当前版本、可用版本、启用状态和是否可更新                                                                  |
| Codex 插件更新状态       | 展示 Codex 插件当前版本、可用版本、启用状态和是否可更新                                                                   |
| 单插件检查更新           | 每个插件卡片提供独立“检查更新”按钮，只读查询是否有新版本，检查期间仅当前按钮展示 loading，完成后在卡片内展示明确结果      |
| 一键检查全部更新         | 顶部按钮并行检查 Claude 与 Codex 的全部插件，期间展示 loading 且不阻塞其他操作                                            |
| 单插件启停               | 在插件页直接启用或禁用单个 Claude / Codex 插件，并展示单项 loading 与失败反馈                                             |
| Marketplace Git 分支切换 | 异步读取 marketplace 仓库分支；切换前提示同市场全部受影响插件，确认后统一启用所选分支并共享 loading，脏工作区会阻止切换   |
| 大模型额度管理器         | 配置 OpenAI、Anthropic 或自定义供应商账户；支持 Base URL + Key 读取兼容模型，安全保存凭据并异步查询已用、总额度与剩余额度 |
| 手动更新 Claude 插件     | 点击“拉取更新”异步调用 claude CLI 更新指定插件（按 scope 更新到正确位置），仅当前按钮展示 loading                         |
| 手动更新 Codex 插件      | 点击“拉取更新”异步刷新 Codex marketplace 并通过 Codex CLI 拉取插件最新版本，仅当前按钮展示 loading                        |
| 工具失败隔离             | Claude 或 Codex 任一插件检查失败时，只影响对应区块                                                                        |
| Finder 定位              | 在 Finder 中打开插件安装路径                                                                                              |
| 更新时间本地化展示       | 将插件最近更新时间转换为北京时间中文格式                                                                                  |

## 应用设置页

| 功能名           | 一句话用途                                                                 |
| ---------------- | -------------------------------------------------------------------------- |
| 主题切换         | 浅色 / 深色 / 跟随系统三种主题，持久化保存                                 |

| Codex 目录配置   | 自定义 Codex 配置根目录（默认 ~/.codex）                                   |

| 路径保存 loading | 保存路径并重新探测工具时展示统一 loading，避免重复点击阻塞任务             |

## 公共能力（前端）

| 功能名             | 一句话用途                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| Ant Design UI 基座 | loading、按钮、徽章、卡片、空状态与 visual-worktree 保持一致                                                                          |
| 控制台式侧边导航   | 使用左侧固定导航承载概览、配置、能力、插件与技能入口，主内容区独立滚动                                                                |
| 工具层级导航       | 使用 Ant Design Menu 将 Codex、Claude Code 作为一级分组，配置、MCP、Hooks、Agents、插件与技能作为各自二级入口，并隔离展示对应工具内容 |
| 黑白石墨深浅主题   | 默认深色主题，并保留浅色 / 跟随系统，所有语义色与 Ant Design token 同步为非纯黑纯白的低饱和中性体系                                   |
| 侧边栏操作图标     | 主题切换、设置入口与关闭按钮使用 Ant Design 图标并保留中文无障碍名称                                                                  |
| AntD 主题同步      | Ant Design 组件跟随浅色、深色与系统主题偏好切换                                                                                       |
| 配置项 AntD 表单化 | 可视化配置项使用 Collapse、Form、Select、Switch、Input 与 TextArea 承载，统一选项与编辑体验                                           |
| 复杂字段内联编辑   | JSON、TOML 对象和字符串列表字段展开后直接显示大文本框，合法内容自动同步，非法 JSON 保留草稿并提示                                     |
| 配置模块层次优化   | 配置文件头、路径元信息、排序工具条、分组区域与字段行独立模块化展示，减少多配置模块粘连在一起的观感                                    |
| 设置抽屉 AntD 化   | 设置入口使用 Drawer 承载主题、路径和官方来源配置，减少自定义弹层样式                                                                  |

## 公共能力（后端）

| 功能名                | 一句话用途                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------- |
| Electron 安全桥       | 通过 preload 暴露受限 `window.api`，渲染进程不直接拥有 fs/shell 能力                            |
| 偏好持久化            | 所有可配置项落盘到 ~/.visualAiCoding/preferences.json                                           |
| 配置语法校验          | 保存 JSON / TOML 前做语法校验，避免写坏配置                                                     |
| 原子写入              | 写临时文件 + rename 替换，防止写入中途崩溃损坏配置                                              |
| 偏好损坏保护          | 偏好文件损坏时备份为 .corrupted 再回退默认值                                                    |
| 登录 shell PATH 解析  | 修正 macOS GUI 应用 PATH 不继承问题，保证能找到 claude / code CLI                               |
| 官方设置同步缓存      | 从官方文档同步 Claude / Codex 配置字段并缓存到 ~/.visualAiCoding/official_settings_sources.json |
| 在 VSCode 打开        | 调用 code CLI 打开文件或目录                                                                    |
| Finder 定位           | 调用 open -R 在 Finder 中显示路径                                                               |
| Electron 启动冒烟测试 | 构建后启动 Electron，验证窗口加载和 preload API 可用                                            |
| 应用自动更新          | 启动时检查 GitHub Release，新版本下载完成后再允许用户安装并重启                                 |
